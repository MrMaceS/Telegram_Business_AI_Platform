> Актуальный объём — TZ.md 5.0: первичный отбор кандидатов. Инструкция ниже относится к исходному ядру 0.2.0. Рекрутинговый workflow команда добавляет отдельно. Ollama/benchmark необязательны для фиксированных ответов. Новый сценарий и новые контакты не появятся от простого запуска старого ядра.

# Команде: установка и эксплуатация

Начните с `START_HERE.md` и `TZ.md`. Пакет — заготовка, до реальной приёмки держать STOP. Для данного ноутбука использовать нативный Python/Ollama, без Docker/WSL.

## 1. Что делает команда, что делает владелец

Команда устанавливает программы, настраивает бот, контакты, инструкции, запускает тесты, помогает с подключением и показывает команды. Владелец в своём Telegram создаёт бота через официальный @BotFather либо предоставляет уже созданного, разрешает Business mode и выбирает бота в настройках Telegram Business → чат-боты. Точные названия пунктов могут зависеть от языка/версии клиента. Выдать только необходимые права отвечать выбранным рабочим контактам; не давать управление подарками/балансом и прочие ненужные разрешения.

Токен вводится локально в скрытый ввод `setup`; не отправлять в групповые чаты, ZIP или репозиторий. Владелец открывает личный чат с этим ботом и нажимает Start для служебных команд и уведомлений. Пароль аккаунта, QR-вход и SMS-коды не требуются. Для настройки нужны 5–10 утверждённых ответов и один тестовый контакт; реальные инструкции команда собирает у владельца.

## 2. Программы и местные данные

1. Установить 64-битный Python 3.12+ с https://www.python.org/downloads/windows/ и Ollama с https://ollama.com/download/windows. Записать точные версии в протокол. Исходники стандартной библиотеки Python не требуют pip-зависимостей в runtime.
2. Распаковать комплект, например в `C:\TelegramAssistant`. Работать под выделенной обычной Windows-учётной записью; ограничить NTFS-доступ к `private` и `data` этой учётной записью и SYSTEM/уполномоченным администратором. DPAPI защищает токен для текущего Windows-пользователя, но не шифрует SQLite и файлы. Использовать доступное шифрование диска и защищённую резервную копию.
3. Проверить свободное место: официальный установщик Ollama требует не менее 4 ГБ, модель ещё около 1,4 ГБ; оставить запас для обновлений, истории и файлов. Размер модели на диске не равен потреблению RAM.
4. Остановить Ollama через значок в трее, задать переменные пользователя, затем запустить Ollama заново. Не менять их в профиле других приложений:

```powershell
[Environment]::SetEnvironmentVariable('OLLAMA_NO_CLOUD','1','User')
[Environment]::SetEnvironmentVariable('OLLAMA_HOST','127.0.0.1:11434','User')
[Environment]::SetEnvironmentVariable('OLLAMA_NUM_PARALLEL','1','User')
```

5. В новом PowerShell выполнить `ollama pull qwen3:1.7b`. Зафиксировать `ollama --version`, `ollama list` и digest модели. Используется локальная модель, облачный аккаунт Ollama не нужен. Не заменять тег на `:cloud`. Качество/скорость модели в этом пакете пока не измерены.

## 3. Подключение

Открыть PowerShell в папке комплекта. Просмотреть `windows.ps1` перед запуском. Если Windows блокирует локальный проверенный скрипт, разрешить его только для текущего процесса; не отключать общую политику безопасности компьютера.

```powershell
.\windows.ps1 setup
.\windows.ps1 inspect
```

`setup` создаёт `.venv`, `config.json` и защищённый DPAPI-токен. Он ничего не отправляет собеседникам. `inspect` делает getMe/getWebhookInfo/getUpdates и показывает только ID, а не текст сообщений или токен. Использовать его только при остановленном ассистенте и других получателях обновлений. Существующий webhook скрипт не удаляет: сначала выяснить, какой системе он принадлежит. Не отключать рабочий Make-сценарий вслепую.

В `config.json` заменить примерные значения: `client_id`, `owner_id`, `business_owner_id`, разрешённые `contacts`, утверждённые `faqs` и `instructions`. ID владельца получают из его `/start`, ID Business-владельца — из Business connection, ID тестового исполнителя — из его входящего сообщения. При отсутствии события подключения повторить подключение собственного бота под контролем владельца; это не обещание восстановления старой истории. Не использовать публичного стороннего «бота для ID» и не пересылать ему рабочие сообщения.

В исходниках никакие ID не менять. Пример DEMO-001 не является реальным заданием; заменить либо удалить. `--check` проверяет структуру и файлы, но не доказывает правильность ID или полномочий.

```powershell
.\windows.ps1 check
.\windows.ps1 test
.\windows.ps1 benchmark
.\windows.ps1 run
```

`benchmark` обращается только к локальной модели с искусственными вопросами, не пишет в Telegram. В первом вопросе учитывается загрузка модели. Сохранить результаты и замерить отдельно RAM через Диспетчер задач. Проверить 10 реальных рабочих вопросов; не считать совпадение FAQ доказательством качества всей переписки. Если вопросы FAQ тоже всегда эскалируются — модель не прошла проверку, даже если критические вопросы обработаны безопасно.

## 4. Управление

В личный чат владельца с ботом:

| Команда | Действие |
|---|---|
| `/status` | Общий STOP, режимы и задания |
| `/resume` | Снять общую паузу; ручные диалоги не возобновляются |
| `/stop` | Запретить новые отправки в рабочие диалоги |
| `/manual 123456` | Передать указанный диалог человеку |
| `/auto 123456` | Вернуть автоответы в диалоге при снятом общем STOP |
| `/reply 123456 Текст` | Отправить конкретный утверждённый текст; общий STOP/права/окно продолжают действовать |
| `/pending` | Неясные/неуспешные отправки и события для сверки |
| `/assign 123456 TASK-1` | Назначить задачу из конфигурации |
| `/issue 123456` | Отправить назначенное задание и файлы |
| `/accept 123456` | Зафиксировать решение владельца о приёмке |
| `/files 123456` / `/file 5` | Список полученных файлов / файл владельцу |

Неизвестный вопрос переводит диалог в ожидание владельца; `/reply`, затем `/auto` возвращают обслуживание. Перед ручным ответом всегда явный `/manual` либо пауза бота в настройках Telegram. Обнаружение исходящего владельца предусмотрено, но доставка такого события должна быть проверена на реальном подключении.

`/stop` запрещает новые бизнес-отправки, но приём/сохранение файлов и служебные уведомления владельцу продолжаются. Если нужно остановить вообще всю обработку — закрыть процесс. После подтверждения STOP уже начатая до него отправка в Telegram ещё могла дойти. Пачка сообщений объединяется контекстом: ответ даётся по последнему, отдельный ответ на каждый фрагмент не гарантируется.

## 5. Повседневная работа и резервная копия

Ноутбук работает от сети и не уходит в сон; экран можно выключать. Закрытие крышки/отключение питания/пропажа интернета могут остановить ответы. Команда настраивает подходящий режим питания с владельцем. Обновления и перезагрузка Windows сохраняются; после рестарта ядро стартует в STOP и требует `/resume`.

Для автозапуска команда создаёт задачу Windows Task Scheduler для текущего пользователя при входе: запуск PowerShell с `-File "C:\TelegramAssistant\windows.ps1" run`, рабочая папка `C:\TelegramAssistant`; запрет параллельного экземпляра, перезапуск при сбое с задержкой. Отдельно проверить Ollama при входе. Это не запуск до входа пользователя и не гарантия 24/7. Оба процесса должны работать под тем Windows-пользователем, который создал DPAPI-токен.

Перед обновлением: `/stop`, закрыть процесс, сделать копию. Пример в PowerShell из папки проекта:

```powershell
$env:PYTHONPATH = "$PWD\src"
.\.venv\Scripts\python.exe -m assistant_core.ops backup .\data .\backup-2026-10-06
.\.venv\Scripts\python.exe -m assistant_core.ops restore .\backup-2026-10-06 .\restored-data
```

Копия должна лежать вне `data`; выбранный путь не должен существовать. Хранить также утверждённый config и материалы; DPAPI-файл переносим только с тем же профилем пользователя, на новом компьютере токен вводят заново. Восстановление требует нового пустого пути и проверяет SHA-256. Перед переключением на восстановленную базу сверить `/pending`; никакого слепого повторения исходящих сообщений. Не открывать старый код на новой схеме БД без проверки совместимости; для отката восстановить согласованную копию кода, конфигурации и данных.

Журнал состояния — таблицы `audit`, `inbox`, `outgoing` в SQLite; `heartbeat` и команда `ops health .\data` проверяют только активность цикла, не доступность Telegram/качество AI. При ошибках смотреть `/pending`. Полные тексты лежат в локальной истории/inbox, поэтому диагностические выгрузки обезличивать; в чат поддержки не отправлять базу. Автоматического удаления истории в заготовке нет: перед промышленным запуском согласовать срок хранения, удаление и объём диска. Еженедельно проверять свободное место и делать копию.

## 6. Как дорабатывать

Код/тесты хранить в Git без `config.json`, `data`, `private`, `.env`. Изменение транспорта — `telegram.py`; модель/промпт — `ai.py`; правило — `workflow.py`; состояние — `storage.py`. Например, новую команду отчёта добавить в `Engine.command`, читающую только текущую Store, затем проверить права владельца и STOP. Новую платную модель без согласования расходов не подключать.

На новую компанию копировать только чистый шаблон и код, с отдельным ботом, данными и Windows-профилем/изолированным окружением. Токены/истории первого клиента не копировать. Не запускать разных клиентов из общей рабочей папки. Релиз 0.2.0 добавил состояния RECEIVED/PENDING в существующую схему: возврат на 0.1.0 напрямую не поддерживается; использовать согласованную копию. Реального второго клиента и SaaS пока нет.
