# Чек-лист установки на Windows заказчика (роль 4)

Выполняется командой вместе с владельцем (удалённый доступ на время установки). Пароль Telegram и SMS-коды НЕ нужны.

1. [ ] Выделенная обычная учётная запись Windows — под ней создаётся токен (DPAPI привязан к пользователю). **Все команды `windows.ps1` (кроме `power`) выполнять под этим пользователем.** `harden` выдаёт права на `$env:USERNAME`: если запустить его из окна администратора под другой учётной записью, права получит не тот пользователь. `power` требует администратора (при необходимости отдельное окно).
2. [ ] Python **3.12 или новее (64-bit)** (3.12, 3.13, 3.14 подходят) с python.org, галочка «py launcher». Записать версию: `py -0`.
3. [ ] Распаковать ZIP в `C:\TelegramAssistant`. Просмотреть `windows.ps1`.
4. [ ] `Set-ExecutionPolicy -Scope Process Bypass` (только для окна PowerShell, не глобально).
5. [ ] `.\windows.ps1 setup` → вставить токен BotFather (ввод скрыт).
5a. [ ] **Шифрование диска.** Settings → Privacy & security → Device encryption / BitLocker (Pro: `manage-bde -status`). SQLite и файлы НЕ шифруются, в них персональные данные кандидатов. Записать результат в протокол; если шифрования нет — сообщить владельцу.
5b. [ ] **Чужой webhook / Make.** Перед `inspect` убедиться, что другие системы не получают обновления этого бота. Если `inspect` показал webhook — НЕ удалять, спросить владельца, чей он. Make по ТЗ не подключаем.
6. [ ] Владелец: BotFather → бот → Business mode; Telegram → Business → Chatbots → выбрать бота, права: только ответы (can_reply), выбранные чаты. Открыть чат с ботом → Start.
7. [ ] `.\windows.ps1 inspect` (бот остановлен, чужих webhook нет) → записать owner ID, connection ID, can_reply.
8. [ ] Заполнить `config.json`: `client_id`, `owner_id`, `business_owner_id` (из inspect; не из публичных «ботов для ID»). `contacts` в текущем коде допуск не определяет (обслуживается любой личный чат из области Business, кроме чатов владельца): поставить `[]`. Удалить пример DEMO-001 и старые FAQ про сдачу заданий. Не править ID в исходниках. Пока в конфиге остаются заглушки 100000001/100000002, `windows.ps1 run` отказывается запускаться (а `check` покажет предупреждение), потому что `check` сам по себе ID не проверяет.
8a. [ ] **Область обслуживания.** Её задаёт Telegram: Business → Чат-боты → какие чаты доступны боту. Настроить вместе с владельцем и записать (нужно для проверки R13).
8b. [ ] **Материалы без изменений.** `Get-FileHash examples\materials\vacancy_conditions.txt, examples\materials\company_presentation.pdf -Algorithm SHA256` — сравнить с `MANIFEST_SHA256.txt`, записать в протокол (B10, R05).
9. [ ] `.\windows.ps1 harden` (NTFS-права).
10. [ ] PowerShell **от администратора**: `.\windows.ps1 power` (без сна, крышка = ничего).
11. [ ] `.\windows.ps1 check` и `.\windows.ps1 test` — зелёные. Покрытие: `.\.venv\Scripts\python.exe -m pip install coverage`, затем `.\windows.ps1 coverage` (должно быть 100%).
12. [ ] Проверить ссылку New work вручную (без вступления от имени владельца).
13. [ ] `.\windows.ps1 run` → в чате владельца «Ядро запущено в STOP» → `/resume`.
14. [ ] Реальная приёмка по `docs/TEST_PROTOCOL.md` раздел 2 (тестовый второй аккаунт-кандидат).
15. [ ] `.\windows.ps1 autostart-install` → перезагрузка → **вход в Windows** (запуск происходит при входе пользователя) → бот поднялся в STOP → `/resume`. `.\windows.ps1 status` и `.\windows.ps1 health` показывают задачу и heartbeat.
15a. [ ] **Восстановление после сбоя:** при работающем боте завершить процесс (`Stop-Process -Name python -Force` под тем же пользователем) → в течение ~1–2 минут Планировщик должен перезапустить задачу (до 5 попыток с интервалом 1 минута) → бот снова в STOP → `/resume`. Если перезапуска нет — записать как дефект, сообщить команде. Затем запуск второй копии при работающей: вторая не стартует (замок `data\runtime.lock`).
16. [ ] `.\windows.ps1 backup` (перед этим `/stop` и закрыть бота; копия в `C:\TelegramAssistant-backups\`, рядом `-config` с настройками и материалами); тест restore в новую папку.
17. [ ] Передать владельцу `docs/OWNER_GUIDE.md`, показать /stop, /resume, /manual, /auto, /reply, **/resume_candidate**, /status, /pending; backup/restore и безопасное обновление (ТЗ раздел 5).
16a. [ ] **Restore (вручную, `windows.ps1` его не делает):** `/stop`, закрыть бота, затем
   `$env:PYTHONPATH="$PWD\src"; .\.venv\Scripts\python.exe -m assistant_core.ops restore <папка_backup> .\restored-data` (путь НОВЫЙ, не существует). После — `/pending`, ничего не повторять вслепую. Записать результат в R14.
17a. [ ] **Срок хранения истории:** спросить владельца, сколько хранить переписку кандидатов и как удалять (автоудаления нет). Записать решение в протокол.
17b. [ ] Договориться о еженедельной проверке: свободное место на диске + `.\windows.ps1 backup` (и копия вне ноутбука).
18. [ ] Ollama НЕ ставить (ТЗ 5.0: LLM необязательна; launcher сам задаёт `AI_MODE=faq`). Действие `benchmark` не использовать: оно для Ollama.
