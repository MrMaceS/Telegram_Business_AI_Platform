# Как изменить сценарий без правки кода

Тексты, условия, фразы и порядок сообщений бота хранятся в одном файле: `examples/recruitment.scenario.json`. На установке это может быть другой путь, он указан в `config.json` в поле `recruitment_scenario`. Программу трогать не нужно.

## Что можно менять

| Что | Где в файле |
|---|---|
| Текст условий вакансии | файл из `conditions_file` (обычный `.txt`) |
| Версия условий | `conditions_version` |
| PDF-презентация | `presentation_file` |
| Ссылка на группу | `group_invite_url` |
| Ответ на неизвестный вопрос | `unknown_question` |
| Ответ на отказ | `decline_message` |
| Фразы «обращение по вакансии» | `phrases.vacancy` |
| Фразы согласия | `phrases.consent` |
| Фразы отказа | `phrases.decline` |
| Что и в каком порядке бот отправляет после согласия | `after_consent` |

### Сообщения после согласия (`after_consent`)
Это список, и бот отправляет его по порядку, сверху вниз. Каждое сообщение — одно из двух:

```json
{"id": "pdf", "type": "document", "caption": "Подпись к файлу", "name": "презентация"}
{"id": "inv", "type": "text", "text": "Ссылка на группу: {url}", "name": "приглашение"}
```

- `id` — короткое латинское имя, своё у каждого сообщения. По нему бот помнит, что уже отправил, поэтому **не меняйте `id` у сообщений, которые кандидаты уже получают**.
- `type`: `"document"` — файл, `"text"` — текст.
- `file` — путь к файлу для `document`. Если не указан, отправляется `presentation_file`.
- `caption` — подпись к файлу (до 1000 символов). `text` — текст сообщения (до 3900 символов).
- `{url}` в тексте бот заменит на `group_invite_url`.
- `name` — как шаг называется в уведомлениях вам (необязательно).

### Фразы
- Бот не различает большие и маленькие буквы, «ё» и «е», знаки препинания.
- Согласие и отказ ищутся **целыми словами**: «подходит» не сработает внутри «не подходит».
- Обращение по вакансии ищется **по части слова**: «ваканси» найдёт и «вакансия», и «вакансии».
- Список в файле **заменяет** встроенный, а не дополняет его. Если удалить весь раздел `phrases`, бот вернётся к встроенным спискам.
- Защита от ошибок в коде остаётся всегда: сообщение с вопросом, с «не», «но», «если», «хотя» и подобными словами бот согласием не считает и передаёт вам.

## Пример: сначала ссылка, потом презентация и отдельное «спасибо»

Было:
```json
"after_consent": [
  {"id": "pdf", "type": "document", "caption": "Условия согласованы. Направляю презентацию компании:", "name": "презентация"},
  {"id": "inv", "type": "text", "text": "Спасибо! Ваше согласие зафиксировано. Ознакомьтесь с презентацией компании и присоединитесь к группе: {url}", "name": "приглашение"}
]
```

Стало:
```json
"after_consent": [
  {"id": "inv", "type": "text", "text": "Ссылка на группу: {url}", "name": "приглашение"},
  {"id": "pdf", "type": "document", "caption": "А это наша презентация", "name": "презентация"},
  {"id": "thanks", "type": "text", "text": "Спасибо! До встречи в группе."}
]
```

## Как применить изменения
1. Сохраните файл в кодировке UTF-8.
2. Проверьте его: `.\windows.ps1 check`. Если в файле ошибка (пустой текст, нет файла, одинаковые `id`, неверный `type`), бот назовёт её и **не запустится**: так он не начнёт работать с неправильным сценарием.
3. Перезапустите бота. Изменения применяются только при запуске.
4. Бот запустится в STOP. Проверьте `/status` и отправьте `/resume`.

## Важно
- **Меняете текст условий — меняйте и `conditions_version`** (например, `2026-10-06-v1` → `2026-11-01-v2`). Согласие привязано к версии условий: кандидаты, которые согласились на старую версию, не получат пакет повторно, а новые получат новые условия.
- Кандидаты, которые уже получили пакет, ничего повторно не получат.
- Поля `vacancy_trigger_examples` и `explicit_consent_examples` — только примеры для документации. Бот ищет фразы из `phrases`.
- Нельзя поменять сами этапы (условия → согласие → пакет) и правила безопасности (STOP, ручной режим, передача вопросов вам). Это защищено кодом.

- **Добавлено:** ответ на отказ (`decline_message`), подпись к PDF, фразы вакансии, согласия и отказа (`phrases`), порядок и состав сообщений после согласия (`after_consent`), проверка файла сценария при запуске.
